# Findings

- [Fixed: the action page offered only Try again for errors a retry can't fix](action-page-failures-have-no-way-back.md) - On /auth/action/, a failure such as a turned-off account landed in a state whose only action was Try again; the failed and saved states now also offer Go home.
- [Fixed: the /auth/action/ page's header had no back link](action-page-header-has-no-back-link.md) - The action page rendered the shared Header with a title only, so a person who arrived from an email had no link out of the page except the buttons its states offered; the header now links back to /.
- [Fixed: the action page updated the router during render](action-page-updates-router-during-render.md) - The /auth/action/ page cleaned the address bar while React was rendering, and Next's history patch updated the Router, which React refuses; the cleanup now runs in a queued microtask, still before paint.
- [Any member can add a signed-up person to their group without asking](add-to-group-without-consent.md) - AddFriend with a group adds anyone found by email to the caller's group, skipping AddGroupMember's friends-only rule; the person gets a push with the group's title, and the group sees their email.
- [Fixed: the admin logs page was open to every signed-in user](admin-logs-unprotected.md) - The /logs page listed every Log row, including logged request bodies, to anyone with a session; the page and the Log table were removed.
- [Fixed: the Android splash shrank into a card when the app opened](android-splash-shrank-on-hand-over.md) - On Android 17 the TWA splash shrank into a dimmed card while the browser window scaled in, because androidbrowserhelper turned the window animation off only after finish(); LauncherActivity now turns it off before.
- [The biometric lock isn't exempt on /auth/action/](biometric-lock-covers-action-page.md) - A signed-in person with a registered passkey who opens a reset or verify link gets the uncloseable lock dialog over the page.
- [Button with asChild throws because it gives Radix Slot two children](button-as-child-throws.md) - components/ui/button.tsx passes two children to Radix Slot when asChild is set, and Slot accepts one, so any use of asChild fails at render.
- [Fixed: the Clerk webhook wasn't verified](clerk-webhook-unverified.md) - POST /api/webhook/clerk trusted any request body, so anyone could create users or overwrite a user's email, name and images; the webhook and Clerk were removed.
- [Fixed: Firebase config for iOS was committed](committed-firebase-config.md) - packages/ios/src/Splitify/GoogleService-Info.plist, which holds the iOS app's Firebase API key and project ids, was tracked in git; it is untracked now, but the key stays in history.
- [Fixed: a contact who signed up kept the contact's id](contact-signup-keeps-contact-id.md) - When a contact signed up, Clerk's webhook kept the spuser_ id on their row, while their session carried Clerk's id, so the app couldn't find them; the merge function now moves the contact's rows to the Firebase uid.
- [Delete account has no guard against a second submit while the dialog closes](delete-account-allows-second-submit-while-closing.md) - handleDelete in the profile's delete-account action closes the dialog and sets deleting in the same step, so a second Enter or click during the dialog's exit animation can call deleteMyAccount twice.
- [Deleting an account leaves the person's saved cache in IndexedDB on the device](deleted-account-leaves-saved-cache-on-device.md) - The delete-account action signs out through Firebase directly and never calls clearSavedCache, so the deleted person's groups and expenses stay in their IndexedDB entry.
- [A local pnpm test:e2e writes its users and groups into the developer's .emulator-data](e2e-writes-into-local-emulator-data.md) - The e2e run starts scripts/dev.mjs, which imports and exports .emulator-data, so local runs leave test users and groups in the developer's emulator data; CI starts empty.
- [Fixed: The Hosting emulator's CSP may have blocked Google sign-in locally](emulator-csp-blocks-auth-iframe.md) - firebase.emulators.json's Content-Security-Policy frame-src had neither 'self' nor the Auth emulator's origin, so Google sign-in through the Hosting emulator may have been blocked; the generator now keeps the first and adds the second.
- [The expense form restores stale unticks when the group changes from A to B and back with no amount](expense-form-restores-stale-unticks.md) - onGroupChange clears the equal-split edits only when an amount is entered, so switching group A to B and back to A without one lays A's old unticks back on, where the old effect ticked everyone.
- [Fixed: A Google sign-in could stay signed in with no User row if sign-out also failed](google-sign-in-signout-failure-keeps-session.md) - When UpsertMe failed after a Google redirect and Firebase Auth's sign-out then failed too, the session stayed, and the sign-in form sent the person into the app without their User row.
- [Fixed: the Gradle 9.8.2 wrapper bump broke the Android build](gradle-9-8-broke-android-build.md) - Dependabot moved the Android wrapper from Gradle 8.13 to 9.8.2, which AGP 8.13 can't run on; the wrapper is back on Gradle 9.5.1 and Dependabot ignores Gradle 9.6 and later.
- [The HTTP guard accepts an ID token revoked by an account deletion](guard-accepts-revoked-id-tokens.md) - guard calls verifyIdToken without checkRevoked, so an ID token issued before an account was deleted still passes on reports and webauthn for up to an hour.
- [Fixed: the session password was hard-coded](hardcoded-session-password.md) - The iron-session password that sealed the WebAuthn challenge cookie was a literal in four route files, so it was in git history; the webauthn function reads it from the SESSION_PASSWORD secret.
- [The iOS WebView allows any script-started navigation and force-casts a private key](ios-webview-allows-other-navigations.md) - WebView.swift lets a navigation of type other through and reads a private WebKit key with as! Int, which would crash the app if WebKit stopped answering it.
- [Fixed: writes didn't check who may change what](missing-authorization-on-writes.md) - Any signed-in person could update or delete any group or expense, add anyone to any group, rename any user and record expenses as someone else; SQL Connect's operations now check membership.
- [Fixed: group reads didn't check membership](missing-group-membership-checks-on-reads.md) - Several read routes and actions only checked for a session, so any signed-in person could read any group's expenses, members, shares and reports by id; SQL Connect's queries and the reports function now check membership.
- [Offline gaps that were left open or not checked](offline-gaps-unchecked.md) - A connection that is up but carries no data still shows a load error over saved data; the update toast, push through the merged worker and a clean test:rules run were not confirmed.
- [Another tab can write a signed-out person's saved cache back after it was deleted](other-tab-rewrites-signed-out-saved-cache.md) - The set of cleared people in the saved-cache code is per tab, so a background tab that hasn't seen the sign-out keeps saving and recreates the entry that sign-out deleted.
- [A privacy page that loaded the ad script keeps it if the visitor signs in from another tab](privacy-page-keeps-ad-script-after-sign-in.md) - app/adsense.tsx renders the ad script only while Auth reports signed-out, but a /privacy/ document that already loaded it keeps it running if the visitor signs in from another tab.
- [Fixed: push-notification routes were an open relay](push-notification-open-relay.md) - Any signed-in person could push any text to any user, and forge activity entries in any group under another person's name; pushes are now sent by Cloud Functions triggers that take nothing from a request.
- [Fixed: the query provider remounted every page at auth restore, so one-shot mount effects ran twice](query-provider-remounts-pages-at-auth-restore.md) - The query provider was keyed by uid, so the whole page subtree remounted once auth restored and any one-shot mount effect ran twice; the provider no longer has a key.
- [Fixed: React Compiler lint rules flagged six components](react-compiler-lint-warnings.md) - eslint-plugin-react-hooks 7 flagged a synchronous setState inside an effect in five components and an impure call during render in scroll-to; all are rewritten and the rules are back at the preset's level.
- [reloadEmailVerified doesn't wait for auth to restore](reload-email-verified-skips-auth-restore.md) - A verify reply that lands before Firebase Auth restores the signed-in person may leave the verify banner up until the next reload; inferred from the code, not reproduced.
- [The reset page's offline note says "Connect to sign in."](reset-offline-note-says-sign-in.md) - The /auth/action/ reset form reuses the sign-in screens' offline note, so a person setting a new password offline is told to connect to sign in.
- [A remount after a reset save that lost its reply can say "expired"](reset-remount-after-lost-reply-says-expired.md) - If the password save's reply is lost and the page then remounts, the check runs without the saved attempts and a spent code reads "expired" where "may already be changed" is right.
- [A second friend from before the fix becomes a contact's sole friend when its creator deletes their account, and can then change its email](second-friend-becomes-sole-friend-on-creator-deletion.md) - UpdateContact lets a contact's sole friend change its email, and deleting the creator's account removes their friendship, so a remaining pre-fix second friend can then point the contact at an address it owns.
- [Sign out can stay loading if removing the push token never answers](sign-out-can-hang-on-push-token-removal.md) - unregisterThisDevice in lib/push/register.ts awaits the token removal with no deadline, so Sign out on Profile stays in its loading state if that call hangs.
- [Fixed: after email sign-up the page stayed on an empty sign-up form](sign-up-stays-on-empty-form.md) - The keyed query provider remounted the sign-up form when sign-in finished, which dropped its created state and left an empty form; fixed by following the saved cache without a key.
- [Functions triggered by SQL Connect mutations don't run in the local emulator](sql-connect-triggers-not-run-locally.md) - mergeContactOnSignUp and the three push senders never load in the Functions emulator, so locally signing up merges no contact and sends no push.
- [A contact made before the fix with two friends can be renamed but not re-emailed by either](two-friend-contact-cannot-be-re-emailed.md) - UpdateContact lets only a contact's sole friend change its email, so a contact that already has two friends from before the fix is stuck on its current email.
- [toUserMessage doesn't match the functions/unauthenticated code, so a callable's sign-in error shows the generic text](unauthenticated-error-not-mapped.md) - toUserMessage compares the error code with unauthenticated, but a callable's code is functions/unauthenticated, so only a message it lists, such as deleteMyAccount's stale sign-in line, gets a readable answer.
- [The verify-banner dismissal's storage catch blocks log nothing](verify-banner-storage-failures-are-silent.md) - readVerifyBannerDismissal and writeVerifyBannerDismissal swallow a localStorage error without logging it, so a browser that blocks storage shows the banner on every visit with nothing in the console to say why.
- [Fixed: the WebAuthn counter wasn't saved](webauthn-counter-not-saved.md) - After a successful check the authenticator's new signature counter was set on an in-memory copy and never written back; the webauthn function now saves it.
