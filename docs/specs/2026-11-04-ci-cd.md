# Spec: CI/CD with GitHub Actions and a service account

Date: 2026-11-04 · Branch: `feat/offline-pwa-firebase`

## Why

Splitify has no CI, and nothing deploys its Firebase backend. The developer wants the CI/CD of their flash-cards
project (`/Users/ankitkumarpandit/Documents/stuff/projects/flash-cards`, its `.github/`, `firebase.json` and README
"Deploy" section) copied as closely as possible. Decisions:
[CI/CD](../../knowledge/decisions/ci-cd-github-actions.md),
[budget kill switch](../../knowledge/decisions/budget-kill-switch.md).

## Scope

In: `ci.yml`, `deploy.yml`, `codeql.yml`, `dependabot.yml`, `.nvmrc`, the Firebase CLI pinned and run with `npx`,
the functions `predeploy` build, the budget kill switch function, and a README section for the one-time setup.

Out: the hosting deploy and a production build of the site (they arrive with the static build, spec 3; until then
Vercel builds every pull request and serves the live site); an end-to-end job (`decisions/e2e-main-flows` leaves the
runner undecided); Workload Identity Federation.

## What differs from flash-cards, and why

| flash-cards | Splitify | Why |

| kill switch in `us-east1` | kill switch in `asia-south1` | the project's functions region |

## Files

- `.nvmrc`: `24`. `functions/package.json` `engines.node` becomes `24`, and `firebase.json`'s functions runtime
  `nodejs24`, so CI, local and the deployed functions run one Node version.
- `package.json`: the Firebase CLI runs as `npx --yes firebase-tools@15.34.2` in `test:rules` and
  `dataconnect:generate`; new scripts `deploy:functions` and `deploy:dataconnect`.
- `firebase.json` functions block: `"predeploy": ["yarn --cwd \"$RESOURCE_DIR\" build"]` and
  `"ignore": ["node_modules", ".git", "src", "firebase-debug.log", "*.local"]`.
- `.github/workflows/ci.yml`: on `pull_request` and `workflow_call`; `permissions: contents: read`; concurrency
  cancels superseded pull-request runs. One job, timeout 15 minutes: checkout (no persisted credentials), Node from
  `.nvmrc` with the yarn cache, Java 21 (Temurin), install with `--frozen-lockfile --ignore-scripts`,
  `npx prisma generate`, `yarn dataconnect:generate`, `yarn lint`, `yarn tsc --noEmit`, `yarn test`,
  `yarn test:rules`, `yarn audit --groups dependencies --level high`, then in `functions/` an install with
  `--frozen-lockfile`, `yarn build` and the same audit.
- `.github/workflows/deploy.yml`: on push to `main`, and `workflow_dispatch` with a boolean input
  `deploy_dataconnect` (default false). `permissions: contents: read`; concurrency group `deploy-production`, never
  cancelled. Job `ci` reuses `ci.yml`; job `deploy` needs it, uses environment `production` with url
  `vars.APP_URL || 'https://splitify.spanion.in'`, checks that the `FIREBASE_SERVICE_ACCOUNT` secret and the
  `FIREBASE_PROJECT_ID` variable exist and fails naming the missing ones and "See README > Deploy" otherwise,
  installs, writes the key to `$RUNNER_TEMP`, deploys functions with
  `firebase-tools@15.34.2 deploy --only functions --project "$PROJECT_ID" --non-interactive --force`, deploys
  SQL Connect with `deploy --only dataconnect --project "$PROJECT_ID" --non-interactive` only when started by hand
  with `deploy_dataconnect` ticked, and deletes the key file afterwards, whether or not the deploy failed.
- `.github/workflows/codeql.yml`: as flash-cards', on pull requests, pushes to `main` and weekly, for
  `javascript-typescript` and `actions`, `security-and-quality` queries.
- `.github/dependabot.yml`: weekly on Monday, grouped minor and patch updates, for npm at `/` and at `/functions`
  and for GitHub Actions. Major updates of `typescript`, `@types/node` and `prisma` are ignored, as
  `decisions/upgrade-all-dependencies` holds them.
- Every action is pinned to the commit SHA flash-cards uses, with its version in a comment.
- `functions/src/kill-switch.ts` and its export from `functions/src/index.ts`: the budget kill switch.
- `README.md`: a "CI and deploy" section listing the workflows, and a "One-time setup" listing what the developer
  does by hand.

## Deploy credentials

- **Secret** `FIREBASE_SERVICE_ACCOUNT`: the JSON key of a service account `github-deploy@splitify-416321` with:
  Cloud Functions Admin, Cloud Run Admin, Service Account User, Artifact Registry Administrator, Cloud Build Editor,
  Eventarc Admin, Pub/Sub Editor, Firebase Data Connect Admin, Cloud SQL Admin, Service Usage Consumer and Firebase
  Viewer. The plan checks this list against Firebase's documentation for deploying 2nd-gen functions and SQL Connect,
  and the README lists the result.
- **Variables** `FIREBASE_PROJECT_ID` (`splitify-416321`) and optionally `APP_URL`.
- The key is written to a file under `$RUNNER_TEMP` only for the deploy commands, never echoed, and removed in an
  `always()` step.

## Budget kill switch

Copied from flash-cards' `functions/src/killSwitch.ts` and `index.ts`, renamed to this repository's kebab-case
(`kill-switch.ts`):

- `billingKillSwitch`: `onMessagePublished` on topic `budget-alerts`, region `asia-south1`, service account
  `billing-kill-switch@`, `maxInstances: 1`.
- `parseNotification(base64)` returns the notification or `null` for anything that isn't one (no data, bad base64 or
  JSON, a missing `costAmount` or `budgetAmount`, a `budgetAmount` of 0 or less).
- `enforceBudget(notification, projectId, client)` returns `"under-budget"` when `costAmount < budgetAmount`,
  `"already-disabled"` when billing is already off, and otherwise unlinks billing (an empty `billingAccountName`)
  and returns `"disabled"`.
- Logs: the outcome and the notification's amounts, at error level when billing was turned off.
- New dependency in `functions/`: `@google-cloud/billing`.

One-time setup, in the README, as in flash-cards: create the `billing-kill-switch` service account with Project
Billing Manager on this project; enable the Cloud Billing API; deploy; grant that account Cloud Run Invoker on the
`billingkillswitch` service; connect the monthly budget to the `budget-alerts` topic; check the wiring by publishing
`{"costAmount": 0.5, "budgetAmount": 5, "currencyCode": "USD"}`, never a `costAmount` at or above `budgetAmount`.

## Testing

- `functions/src/kill-switch.test.ts`, run by `yarn test:rules` with the other `functions/` tests: each
  `parseNotification` case above, and `enforceBudget` under budget (no billing call), at budget with billing on
  (unlinks, `"disabled"`), and with billing already off (`"already-disabled"`, no update call), against a fake
  `BillingClient`.
- The workflows are checked by running: this branch's pull request runs `ci.yml` and CodeQL, and both pass.
  `deploy.yml` first runs when the branch reaches `main`; with the secret or variable missing it fails with the
  message naming them.
