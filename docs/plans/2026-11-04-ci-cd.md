# CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:implement-with-subagents by default, or ga:implement. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Check every pull request and deploy Splitify's Cloud Functions (and, by hand, its SQL Connect schema) from GitHub Actions with a service account, copied from the flash-cards project, with its budget kill switch.

**Architecture:** A reusable `ci.yml` runs the repository's checks and emulator rule tests; `deploy.yml` reuses it on push to `main`, then deploys with a service-account key written to a temporary file. CodeQL and Dependabot follow flash-cards'. The kill switch is a 2nd-gen Pub/Sub function in `functions/`, its decisions in a module free of SDK imports so they are tested without Google Cloud.

**Tech Stack:** GitHub Actions (the repository is `AKAspanion/splitify` on GitHub; it has no CI yet), yarn 1, Node 24, Java 21 for the emulators, the Firebase CLI as `npx --yes firebase-tools@15.34.2`, Firebase SQL Connect, Cloud Functions 2nd gen (`firebase-functions`, `firebase-admin`), `@google-cloud/billing`, Vitest 5. The reference setup is `/Users/ankitkumarpandit/Documents/stuff/projects/flash-cards` (`.github/`, `firebase.json`, `functions/src/killSwitch.ts`, `functions/src/index.ts`, `README.md` "CI" and "Budget kill switch" sections): read it, never edit it.

**Spec:** [docs/specs/2026-11-04-ci-cd.md](../specs/2026-11-04-ci-cd.md)

## Global Constraints

- Branch `main`; project `splitify-416321`; functions region `asia-south1`.
- The Firebase CLI is `npx --yes firebase-tools@15.34.2`, never a global `firebase`, in scripts and workflows.
- Installs in CI use `yarn install --frozen-lockfile --ignore-scripts`; `postinstall` and `postbuild` run `prisma db push`, so neither `yarn install` without `--ignore-scripts` nor `yarn build` runs in CI.
- Every action is pinned to the commit SHA flash-cards uses, with its version in a trailing comment.
- Workflows declare `permissions: contents: read` at the top, and widen them only per job where a job needs it.
- A secret is never echoed; the service-account key lives in a file under `$RUNNER_TEMP` only while deploy commands run, and is removed in an `always()` step.
- Audits run at `--level high`.
- Nothing is deployed and no GitHub setting is changed while building this plan: the workflows run on GitHub once pushed.

## Checkpoints

None: the policy's `run.checkpoints` is `none`, and the spec asks for none. The run stops only at the end, before pushing.

**Files:**

**Interfaces:**

- Produces: the exported `billingKillSwitch` function (its name, topic, region and service account are what Task 3's README describes).

```ts
// functions/src/kill-switch.ts (no SDK imports)
export interface BudgetNotification { budgetDisplayName: string; costAmount: number; budgetAmount: number; currencyCode: string }
export interface BillingClient {
  getProjectBillingInfo(request: { name: string }): Promise<[{ billingEnabled?: boolean | null }, ...unknown[]]>;
  updateProjectBillingInfo(request: { name: string; projectBillingInfo: { billingAccountName: string } }): Promise<unknown>;
}
export type Outcome = "under-budget" | "already-disabled" | "disabled";
export function parseNotification(base64Data: string | undefined): BudgetNotification | null;
export function enforceBudget(notification: BudgetNotification, projectId: string, client: BillingClient): Promise<Outcome>;

// functions/src/index.ts
export const billingKillSwitch: import("firebase-functions").CloudFunction<unknown>; // onMessagePublished, topic "budget-alerts", region "asia-south1", serviceAccount "billing-kill-switch@", maxInstances 1
```

`billingKillSwitch` parses the message, logs and returns for a non-notification (a warning with the message id), creates one `CloudBillingClient` lazily, takes the project id from `projectID` params or `GCLOUD_PROJECT` (throws when neither is set), runs `enforceBudget`, and logs the outcome with the project id and the notification's amounts, at error level for `"disabled"`.

**Spec:**
- Budget kill switch: "`billingKillSwitch`: `onMessagePublished` on topic `budget-alerts`, region `asia-south1`, service account"
- Budget kill switch: "`parseNotification(base64)` returns the notification or `null` for anything that isn't one (no data, bad base64 or"
- Budget kill switch: "`enforceBudget(notification, projectId, client)` returns"
- Budget kill switch: "Logs: the outcome and the notification's amounts, at error level when billing was turned off."
- Testing: "`functions/src/kill-switch.test.ts`, run by `yarn test:rules` with the other `functions/` tests: each"

**Tags:** `security`, `failure-paths`

**Knowledge:** `apps/functions` (new): the functions in `functions/src/`, the merge trigger and the kill switch, their regions and service accounts. `decisions/budget-kill-switch` stays as it is: `apps/functions` names `functions/src/kill-switch.ts` as its code.

**Acceptance:**
- Given `undefined` or an empty string, when `parseNotification` runs, then it returns `null`.
- Given base64 of `not json`, or of `"just a string"`, or of `null`, then it returns `null`.
- Given base64 of `{"budgetAmount": 5}` (no `costAmount`), or `{"costAmount": 1}` (no `budgetAmount`), or `{"costAmount": "1", "budgetAmount": 5}` (a string amount), then it returns `null`.
- Given base64 of `{"costAmount": 1, "budgetAmount": 0}` or a `budgetAmount` of `-5`, then it returns `null`.
- Given base64 of `{"budgetDisplayName": "Splitify monthly", "costAmount": 4.2, "budgetAmount": 5, "currencyCode": "USD"}`, then it returns those four fields; with `budgetDisplayName` and `currencyCode` missing it returns them as `""`.
- Given `costAmount` 4.99 and `budgetAmount` 5, when `enforceBudget` runs against a fake client, then it returns `"under-budget"` and calls neither client method.
- Given `costAmount` 5 and `budgetAmount` 5 and billing on, then it calls `getProjectBillingInfo({ name: "projects/splitify-416321" })`, then `updateProjectBillingInfo` with `billingAccountName: ""`, and returns `"disabled"`.
- Given `costAmount` 7 over a budget of 5 and billing already off (`billingEnabled: false` or `null`), then it returns `"already-disabled"` and never calls `updateProjectBillingInfo`.
- Given `getProjectBillingInfo` rejects, then `enforceBudget` rejects with that error and never calls `updateProjectBillingInfo`, so the function fails and Pub/Sub retries it.
- Given `functions/src/index.ts`, then `billingKillSwitch` is exported beside `mergeContactOnSignUp`, with topic `budget-alerts`, region `asia-south1`, service account `billing-kill-switch@` and `maxInstances: 1` (checked from the function's endpoint options, as `merge-contact.test.ts` checks its trigger).
