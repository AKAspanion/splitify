# Local dev on emulators, 2140-series ports, pnpm — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:feature-build-team by default, or ga:feature-build. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

Plan, then build; tests with each task. Say 'test-first' or 'spec it first' to work that way.

**Goal:** One command (`pnpm dev`) runs the web app and every Firebase emulator it needs on ports 2140–2150, as the demo project `demo-splitify`, with no real Firebase project, keys or `.env`; and the repository uses pnpm instead of yarn.

**Architecture:** `firebase.json`'s `emulators` block is the one place the emulator ports live. Browser code reads them from a small constants module that a unit test holds equal to `firebase.json`; Node scripts read `firebase.json` directly. `scripts/dev.mjs` starts the functions TypeScript watcher, the emulator suite (with data kept in `.emulator-data/` between runs) and `next dev`, with the emulator env set on the Next process. In development only, `next.config.mjs` rewrites `/api/reports/**` and `/api/webauthn/**` to the Functions emulator, the way Hosting's rewrites do in production. `functions/` stays its own package with its own lockfile, so `firebase deploy` ships it as it does today.

**Tech Stack:** Next.js 16 (static export), Firebase emulators via `firebase-tools@15.34.2` (pinned through `npx`/`pnpm dlx`), SQL Connect, Cloud Functions v2 (onRequest, onCall, `onMutationExecuted` SQL Connect triggers, Pub/Sub), Vitest, GitHub Actions (`.github/workflows/ci.yml`, `deploy.yml`, `codeql.yml`), pnpm 11 (local `pnpm -v` is `11.0.8`).

**Spec:** none — the developer chose plan-then-build for this change, and it is tooling, not product behaviour.

## Global Constraints

- Ports, in this order, and nothing else local outside the 2140 series:

  | Port | Service | Where it is set |
  |---|---|---|
  | `2140` | Next dev server | `package.json` `dev:web` |
  | `2141` | Emulator hub | `firebase.json` `emulators.hub.port` |
  | `2142` | Auth emulator | `emulators.auth.port` |
  | `2143` | SQL Connect emulator | `emulators.dataconnect.port` |
  | `2144` | SQL Connect emulator's Postgres | `emulators.dataconnect.postgresPort` |
  | `2145` | Functions emulator | `emulators.functions.port` |
  | `2146` | Eventarc emulator (SQL Connect triggers) | `emulators.eventarc.port` |
  | `2147` | Pub/Sub emulator (budget kill switch) | `emulators.pubsub.port` |
  | `2148` | Hosting emulator | `emulators.hosting.port` |
  | `2149` | Emulator UI | `emulators.ui.port`, `enabled: true` |
  | `2150` | Emulator logging (UI's log stream) | `emulators.logging.port` |

- Every emulator binds `127.0.0.1` (`host` on each block), matching the addresses the browser code uses.
- The local project is `demo-splitify` everywhere a script starts emulators (the developer's answer, 2026-11-05). `.firebaserc`'s `default` stays the real project, for deploys.
- The Firebase CLI stays pinned at `firebase-tools@15.34.2`.
- Node 24 (`.nvmrc`). The package manager is pnpm: `packageManager` names the exact version, and no `yarn.lock` remains.
- `firebase.emulators.json` is generated by `scripts/emulator-firebase-config.mjs`, never edited by hand, never deployed.
- No real secret is committed. The emulator's `SESSION_PASSWORD` is generated into the gitignored `functions/.secret.local`.

- Produces:

```ts
// scripts/dev-env.mjs (plain JS with JSDoc types)
/** The env `next dev` gets so the browser talks to the emulators as demo-splitify. */
export function webDevEnv(): {
  NEXT_PUBLIC_USE_FIREBASE_EMULATORS: "true";
  NEXT_PUBLIC_FIREBASE_PROJECT_ID: "demo-splitify";
  NEXT_PUBLIC_FIREBASE_API_KEY: "demo-key";
  NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN: "demo-splitify.firebaseapp.com";
};
/** Dev-only rewrites from /api/<fn>/** to the Functions emulator, mirroring firebase.json's hosting rewrites. */
export function functionRewrites(firebaseJson: object, projectId: string):
  { source: string; destination: string }[];
/** Writes functions/.secret.local with a random 48-character SESSION_PASSWORD when the file is missing; never overwrites it. */
export function ensureFunctionsSecret(functionsDir: string): "created" | "kept";
```

- `next.config.mjs` becomes a phase function: `output: "export"` for every phase except `PHASE_DEVELOPMENT_SERVER`, and in that phase only, `rewrites()` returns `functionRewrites(firebase.json, "demo-splitify")`. The production build's config is unchanged.
- `scripts/dev.mjs`: exits with "Run pnpm functions:install first" when `functions/node_modules` is missing; calls `ensureFunctionsSecret`; then starts three children with prefixed output — `tsc --watch` in `functions/`, `pnpm emulators`, and `pnpm dev:web` with `webDevEnv()` merged over `process.env` — and stops all three when any exits or on Ctrl+C.
- `functions/.env.demo-splitify` (loaded by the Functions emulator for that project only): `AUTHN_RP_ID=localhost`, `AUTHN_EXPECTED_ORIGIN=http://localhost:2140`. No secret in it.
